# «فقط برای تو ♡» — ربات تلگرام + Mini App

یک پروسه‌ی پایتونی که هم‌زمان ربات (aiogram 3)، API امن، سرو کردن Mini App و زمان‌بند پیام صبح/شب را اجرا می‌کند.
چون ربات و Mini App یک پروسه و یک دیتابیس‌اند، تداخل و زمان‌بند تکراری وجود ندارد.

## ساختار فایل‌ها (ریشه‌ی مخزن GitHub)
```
bot.py               ← ربات + API + زمان‌بند
webapp/index.html    ← Mini App (CSS و JS داخل همین فایل)
requirements.txt     ← وابستگی‌ها
Procfile             ← web: python bot.py
railway.json         ← فرمان اجرا، health check، یک replica
.env.example         ← فهرست متغیرها (فقط نمونه؛ مقادیر واقعی را commit نکن)
.gitignore
```

## متغیرهای محیطی (Railway ← Service ← Variables)
| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن از BotFather |
| `ADMIN_ID` | شناسه‌ی عددی تلگرام مدیر |
| `ALLOWED_USER_ID` | شناسه‌ی عددی کاربر مجاز |
| `WEBAPP_URL` | آدرس HTTPS سرویس، بدون `/` آخر (مثل `https://xxx.up.railway.app`) |
| `DB_PATH` | مسیر دیتابیس روی Volume، مثلاً `/data/app.db` (پوشه‌ی `media` کنار آن ساخته می‌شود) |
| `TIMEZONE` | `Asia/Tehran` |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | اختیاری. بدون کلید، پیام‌های آماده‌ی متنوع ارسال می‌شود |

شناسه‌ی عددی را از ربات‌هایی مثل @userinfobot بگیر. هر دو نفر باید یک بار ربات را `/start` کنند، وگرنه ربات نمی‌تواند به آن‌ها پیام بدهد.

## استقرار روی Railway
1. کد را در یک مخزن GitHub خصوصی بگذار.
2. Railway ← New Project ← Deploy from GitHub repo.
3. در همان سرویس: **Settings ← Volumes ← Add Volume** با Mount Path = `/data`. (بدون Volume، دیتابیس و فایل‌ها با هر deploy پاک می‌شود.)
4. **Settings ← Networking ← Generate Domain** و آدرس HTTPS را در `WEBAPP_URL` بگذار.
5. متغیرهای جدول بالا را وارد کن (`DB_PATH=/data/app.db`).
6. **Replicas را روی ۱ نگه دار.** (SQLite روی Volume و long polling ربات با چند نمونه جور نیست.)
7. Deploy. در لاگ باید `web server on :...` و `scheduler started` را ببینی.

## BotFather
- `/newbot` برای ساخت ربات و دریافت توکن.
- دکمه‌ی منوی Mini App را خود برنامه هنگام شروع با `setChatMenuButton` تنظیم می‌کند. اگر خواستی دستی هم بگذاری: BotFather ← `/mybots` ← Bot Settings ← Menu Button ← آدرس `WEBAPP_URL`.
- دکمه‌ی «🖥 باز کردن مینی‌اپ» در ربات هم دکمه‌ی inline از نوع `web_app` است (فقط این نوع `initData` امضادار می‌دهد).

## اجرای محلی
```
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # مقادیر را پر کن؛ DB_PATH=data/app.db
export $(grep -v '^#' .env | xargs)
python bot.py
```
تلگرام فقط HTTPS می‌پذیرد؛ برای تست محلی یک تونل (`cloudflared tunnel --url http://localhost:8080` یا ngrok) بساز و آدرسش را در `WEBAPP_URL` بگذار.

## نحوه‌ی کار
- **هویت:** هر درخواست API هدر `Authorization: tma <initData>` دارد؛ سرور امضای HMAC-SHA256 را طبق مستندات رسمی تلگرام بررسی می‌کند (و `auth_date` را تا ۲۴ ساعت می‌پذیرد) و `user.id` را فقط از داده‌ی تأییدشده برمی‌دارد.
- **حریم خصوصی:** تا کاربر مجاز رضایت صریح ندهد، ذخیره‌ی خاطره/عکس/ویس رد می‌شود (هم در ربات هم در API). توقف ثبت و حذف همه‌ی خاطرات از تنظیمات در دسترس است. فایل‌ها فقط با `/api/media/<id>/file` و احراز هویت سرو می‌شوند و نام فایل روی دیسک تصادفی است.
- **زمان‌بند:** ساعت ۶ و ۰۰:۰۰ به وقت ایران؛ هر پیام با کلید `(نوع، روز)` در جدول `schedule_log` به‌صورت اتمیک ثبت می‌شود، پس ری‌استارت پیام تکراری نمی‌سازد و اگر سرور چند دقیقه دیر بالا بیاید جبران می‌کند (۳ ساعت برای صبح، ۹۰ دقیقه برای شب). ارسال ناموفق تا ۳ بار دوباره تلاش می‌شود.
- **Gemini:** فقط یک مضمون کلی در prompt می‌رود، نه خاطره‌های شما. هر خطا یا اتمام سهمیه → پیام آماده.
- **مناسبت‌ها:** سالگرد از تاریخ شروع محاسبه می‌شود. روز دختر مناسبتی قمری است (تاریخ شمسی‌اش هر سال عوض می‌شود)، پس عمداً هاردکد نشده؛ مدیر هر سال تاریخ را از تقویم رسمی در «مناسبت‌ها» ثبت یا اصلاح می‌کند.

## پشتیبان‌گیری و پایداری
- مدیر با `/backup` (یا پنل مدیر ← 💾) یک نسخه‌ی SQLite از دیتابیس در چت می‌گیرد. عکس‌ها و ویس‌ها فقط روی Volume هستند؛ برای نسخه‌ی کامل از Volume بکاپ بگیر.
- هر خطای پیش‌بینی‌نشده‌ی ربات در جدول `error_log` ثبت می‌شود (پنل مدیر ← 🧾) و به کاربر پیام مناسب می‌رود.
- API برای هر کاربر ۲۴۰ درخواست در دقیقه مجاز است؛ صفحه‌ی اصلی با Content-Security-Policy سرو می‌شود. اگر روزی خواستی منبع خارجی دیگری اضافه کنی، `csp` را در تابع `index` به‌روز کن.

## محدودیت‌های شناخته‌شده (صادقانه)
- فقط **SQLite** پیاده‌سازی شده (روی Volume پایدار). `DATABASE_URL` از نوع PostgreSQL پشتیبانی نمی‌شود.
- ویس‌هایی که از تلگرام می‌آیند OGG/Opus هستند و ممکن است در Mini App روی بعضی نسخه‌های iOS پخش نشوند؛ در ربات همیشه پخش می‌شوند.
- ضبط میکروفون به مجوز WebView تلگرام بستگی دارد؛ اگر رد شد، پیام راهنما نشان داده می‌شود و ویس را باید از ربات فرستاد.
- فونت Vazirmatn از Google Fonts می‌آید؛ اگر در دسترس نبود، Tahoma/فونت سیستم جایگزین می‌شود.
- مدل پیش‌فرض Gemini (`gemini-2.5-flash`) را با مستندات فعلی Google چک کن و در صورت نیاز `GEMINI_MODEL` را عوض کن.

## چه چیزی تست شده؟
تست‌شده: کامپایل `bot.py`؛ تبدیل شمسی↔میلادی (رفت‌وبرگشت چند سال + تاریخ‌های مرجع)؛ اعتبارسنجی `initData` (معتبر، دست‌کاری‌شده، منقضی، توکن اشتباه)؛ تشخیص نوع فایل؛ طرح و کوئری‌های SQL؛ نحو JavaScript.
**تست نشده:** اجرای واقعی با تلگرام، Railway، میکروفون و Gemini (در محیط ساخت دسترسی شبکه/تلگرام نبود). اولین اجرا را خودت باید بررسی کنی؛ اگر خطایی در لاگ دیدی، همان‌جا قابل رفع است.
